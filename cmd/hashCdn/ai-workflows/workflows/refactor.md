# 工作流：代码重构

## 适用场景

优化代码结构、性能改进、消除重复逻辑，不改变外部行为。

## 流程

### 1. 确认范围
- 重构涉及哪些函数/模块
- 是否只涉及一版？如果两版都需要重构，分开做

### 2. 设计
- 列出重构前后的函数对应关系
- 确认不改变外部行为（CLI 参数、配置字段、输出日志格式）
- 如果改变内部结构，更新 `dual-version-alignment/SKILL.md` 的速查表

### 3. 执行
- 小步重构，每步跑 `go test -v` 或 `cargo test`
- 保持函数签名和行为不变

### 4. 验证
- 用 `-dry-run` 对比重构前后的输出
- 用 mode 4 做一次完整部署测试，确认行为一致
- 检查另一版是否需要同步重构
