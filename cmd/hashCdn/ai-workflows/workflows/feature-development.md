# 工作流：功能开发

## 适用场景

新增功能或增强现有功能（如新增部署模式、新增 CLI 参数、支持新的资源类型）。

## 流程

### 1. Proposal（提案）
- 明确功能要解决什么问题
- 确认是否影响 Go 和 Rust 两版
- 确认是否需要修改 version.config.json

### 2. Design（设计）
- 列出要修改的文件清单（Go + Rust）
- 如果涉及正则，对照 `dual-version-alignment/SKILL.md` 的速查表
- 如果涉及配置字段，确认两版结构体都需要加
- 如果涉及 CLI 参数，确认两版都需要处理

### 3. Tasks（任务拆分）
- 拆分为 Go 版修改 + Rust 版修改 + 测试验证
- 每个子任务都要标注影响哪一版

### 4. 审查
- 逐项检查 `dual-version-alignment/SKILL.md` 的检查清单
- 确认两版行为一致

### 5. 实现
- 先改 Go 版（单文件，改动集中）
- 再改 Rust 版（对照速查表找对应模块）
- 跑 `go test -v` 和 `cargo test`

### 6. 验证
- 用 `-dry-run` 预览配置是否正确
- 如果涉及部署，用 mode 4 或 5（不替换 CDN）做测试
- 确认输出日志两版一致
